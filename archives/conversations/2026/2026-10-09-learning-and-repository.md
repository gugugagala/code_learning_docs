## 02 用户：个人代码编码能力不强，该怎么提升

个人代码编码能力不强，该怎么提升

### 助手

如果你觉得编码能力不强，最有效的办法是：**选一门语言，用小项目反复练习“拆问题 → 写代码 → 排错 → 验证”这个完整过程。** 不用急着刷很多课程或学习多个框架。

你可以按这个顺序练：

1. **把基础练到能独立使用。**
   重点掌握变量、条件、循环、函数、常用数据结构、文件读写和异常处理。学完一个知识点，关掉教程，自己写一个小例子。

2. **把需求拆成小步骤。**
   比如“统计文件中出现最多的词”，先拆成：读取文件、分词、统计次数、排序、输出。每次只完成一步。写代码卡住时，先检查自己是否能用自然语言说清楚步骤。

3. **做一个范围小、自己用得上的项目。**
   例如文件整理脚本、记账工具或待办清单。先做出能运行的版本，再增加输入检查、错误提示和测试。一个完整的小项目比几个只跟着教程写的项目更能暴露问题。

4. **认真练排错。**
   出错后先读报错，找到对应代码，检查输入和变量值，再提出一个原因并验证。修好之后，记一句“为什么错、怎样发现的”，不要只保存正确代码。

每天可以安排 45～60 分钟：先独立写，再针对卡点查资料，最后整理当天的一个错误或收获。判断进步的标准是：**你能否在没有教程的情况下完成类似任务，并解释代码为什么这样写。**

你也可以把我当成教练，这样使用：

- “先给我提示，不要直接给完整代码。”
- “把这个需求拆成步骤，让我自己实现。”
- “审查我的代码，指出最值得改进的三个问题。”
- “这段代码我看懂了，请出一道变形题检查我是否掌握。”

用 AI 写出的代码，最好自己解释一遍，再关掉答案重写核心部分；否则容易出现“看得懂，但写不出来”。

你现在主要使用什么语言？最容易卡在“想不出思路”“语法不会写”还是“报错不会修”？

## 03 用户：主要使用 C，后续想转 Rust

主要使用 C 后续想转 rust，均有想不出思路，语法不会，算法记不住，报错不会修的阶段。

### 助手

你现在需要的是建立一套稳定的解题和排错流程。**建议先用 C 完成几个小程序，再把其中一个改写成 Rust。** 这样学 Rust 时，你可以专注于语言差异，减少同时处理业务思路和新语法的负担。

你提到的四种困难，可以分别练。

| 困难 | 练习方式 |
|---|---|
| 想不出思路 | 写代码前先写输入、输出、具体例子，再用自然语言列步骤 |
| 语法不会 | 保留一页常用语法笔记；查完后关闭例子，自己写一遍 |
| 算法记不住 | 从具体数据手动执行，理解每一步为什么有效，再实现 |
| 报错不会修 | 每次只处理第一个错误，找到位置、解释原因、修改并验证 |

**遇到题目，固定做这五步。** 比如“统计整数数组中每个数字出现的次数”：

1. 写输入：`[3, 1, 3, 2, 1]`。
2. 写预期输出：`3:2，1:2，2:1`。
3. 手动统计一次，观察自己怎么做。
4. 把过程写成步骤：取一个数 → 判断是否统计过 → 计算次数 → 输出。
5. 先实现最直观的方案，再考虑效率。

暂时没有想到高效算法，也可以先写嵌套循环。先练到能够把正确步骤翻译成代码，再学习优化。

**算法不要只背代码，要记它解决什么问题。** 初期重点练遍历、计数、查找、排序，以及数组和字符串处理。每学一个算法，都回答：

- 它适合什么输入？
- 每一步在维护什么信息？
- 为什么这样做不会遗漏结果？
- 空输入、重复数据、边界值会怎样？

比如二分查找，先记住“有序数据，每次排除一半搜索范围”，然后拿一个数组手动演算。隔几天不看答案重新实现，才能判断是否掌握。

**C 的排错，先让工具提供更多线索。** 使用 GCC 或 Clang 时，可以从这样的编译命令开始：

```bash
cc -std=c17 -Wall -Wextra -Wpedantic -g main.c -o main
```

每次编译后先修第一个错误，后面的错误可能由它引起。程序能编译但结果不对时，用一个很小的输入复现，检查每一步的变量值。对指针和数组问题，重点检查：是否初始化、索引是否越界、指针指向的对象是否仍然有效、字符串是否有结束符。

可以用六周作为第一轮练习，每天约 45～60 分钟：

| 时间 | 重点 | 小任务 |
|---|---|---|
| 第 1 周 | 条件、循环、函数 | 最大值、平均值、数字计数 |
| 第 2 周 | 数组、字符串、边界 | 查找元素、反转字符串、字符统计 |
| 第 3 周 | 指针、结构体、内存 | 用结构体数组管理联系人 |
| 第 4 周 | 文件读写、错误处理 | 给联系人程序增加保存和读取 |
| 第 5 周 | Rust 基础 | 重写前两周的小任务，练 `Vec`、`String`、`match` |
| 第 6 周 | 所有权、借用、`Result` | 用 Rust 重写联系人程序 |

进度可以放慢。进入下一阶段的标准是：你能独立完成核心功能、解释代码，并处理几个边界输入。

使用我时，建议明确要求我保留你的练习机会：

> 我正在练 C。先让我写思路，你帮我检查。卡住时每次只给一个提示，不要直接给完整代码。完成后检查边界情况，再让我自己修改。

排错时则发来**编译命令、完整报错、相关代码，以及预期和实际结果**，让我先解释报错，再引导你定位。

你可以从这道练习开始：**给定一个整数数组，找出最大值，并统计它出现了几次。** 先写自然语言步骤，暂时不用写 C；这能帮助我们判断你首先卡在思路还是代码表达。

## 04 用户：语言熟悉的程度

练习到什么地步才算是对语言熟悉、且有哪些程度

### 助手

**熟悉一门语言的标志是：能独立完成常见任务，解释代码为什么正确，并定位大部分日常错误。** 查语法、查标准库很正常；关键是你知道要查什么，查到后能正确使用。

可以分成五个程度。下面以 C 为主：

| 程度 | 能做到什么 | 自测任务 |
|---|---|---|
| **1. 入门：能表达步骤** | 使用条件、循环、函数；根据清楚的步骤写程序 | 独立完成最大值、计数、数组反转 |
| **2. 基础：能完成小程序** | 使用数组、字符串、结构体、文件；拆分函数；处理异常输入 | 写一个能保存和读取文件的联系人管理程序 |
| **3. 熟悉：能解释和排错** | 理解指针、对象生命周期、内存分配；检查边界；使用编译器警告和调试器 | 排查越界、悬空指针、内存泄漏；解释问题产生的原因 |
| **4. 熟练：能维护项目** | 阅读陌生代码、修改多个模块、设计接口；验证改动；权衡实现方式 | 给已有项目增加功能，同时保持原有功能正常 |
| **5. 深入：能处理复杂问题** | 理解语言规则及平台差异；分析性能、并发、ABI 等问题 | 根据测量结果优化程序，解释正确性与可移植性边界 |

这些程度有重叠，也不是统一认证标准。有人很会写业务代码，但对并发或底层细节了解不多，仍然可以算熟练。

对你来说，**达到第 3 级，可以认为对 C 已经比较熟悉**。具体可以用下面几个问题检查：

- 拿到小需求，能否自己拆步骤，而不必照着完整答案写？
- 能否解释数组、指针、字符串之间的关系？
- 能否说明一个对象什么时候有效，谁负责释放动态内存？
- 面对编译错误或运行结果错误，能否逐步缩小问题范围？
- 能否主动检查空输入、重复数据、长度限制等边界？
- 隔一周重新实现类似功能，能否完成，并解释关键选择？

**最可靠的检验是“独立实现 → 修改需求 → 修复错误”。** 例如完成联系人管理程序之后，再要求你：

1. 支持同名联系人。
2. 限制姓名长度，并处理非法输入。
3. 从固定数组改成动态扩容。
4. 排查一个删除联系人后出现的错误。
5. 给关键行为补上验证。

能完成原版，说明你会实现；能适应这些变化，才更能说明你理解了。

另外，**语言熟悉度与算法能力要分开看**。不会动态规划，不代表不熟悉 C；能背出排序代码，也不代表理解指针和内存。你可以把进步分成三条线：语言表达、问题拆解、调试验证，分别练习。

转 Rust 不需要等到 C 第 5 级。达到第 2 级，并开始理解第 3 级中的内存和生命周期概念，就可以逐步学习 Rust。之后判断自己是否熟悉 Rust，要看能否解释所有权、借用、`Option` 和 `Result`，以及遇到借用错误时能根据数据的生命周期调整设计。

## 05 用户：该如何跟着你学习编程

该如何跟着你学习编程

### 助手

我们可以采用“**你动手，我引导，每次完成一个小任务**”的方式。先用 C 练基础、拆解和排错，再逐步转 Rust。

每次学习按这个流程：

1. **我出一道适合你的题**，明确输入、输出和限制。
2. **你先写自然语言思路**，不会写代码也可以。
3. **我检查思路并给提示**，默认不直接提供完整答案。
4. **你写代码并编译**，把代码、编译命令和报错发来。
5. **我引导你定位问题**，让你自己修改。
6. **完成后做一道变形题**，检查你是否能独立运用。

卡住时可以直接说“没有思路”“这段语法不会”或“报错看不懂”。我会按需要逐步提供：方向提示 → 具体步骤 → 局部代码。需要完整示例时，再一起拆解，之后让你独立重写。

我们会根据你的表现调整难度。判断是否掌握，主要看你能否**独立完成、解释原因、处理边界、适应需求变化**。每几次练习，我会整理你的已掌握内容和薄弱点；隔几天安排一次复习。

现在先做第一题，了解你的起点：

> 给定一个整数数组，找出最大值，并统计最大值出现的次数。
> 例如：`[3, 7, 2, 7, 5]`，结果是最大值 `7`，出现 `2` 次。
> 暂时假设数组至少有一个元素，不需要处理键盘输入。

**先不要写 C 代码。请用自己的话写出处理步骤，并想一想：如果数组里的数全是负数，你的步骤是否仍然正确？** 不需要使用专业术语，也不用担心答错。

   ```bash
   ssh -T -i ~/.ssh/id_ed25519_github -o IdentitiesOnly=yes git@github.com
   ```
